## Abstract
This project classifies individual parking spaces as *empty* or *occupied* from image crops of the PKLot dataset, using Histogram of Oriented Gradients (HOG) features and classical classifiers (linear SVM, Random Forest, Logistic Regression), with no GPU required.

The main goal of the current version is **trustworthy evaluation**. Crops cut from the same camera frame, or from frames minutes apart, are nearly identical, so a random crop-level train/test split lets near-duplicates leak into the test set and inflates accuracy. This repository therefore (i) evaluates with splits that hold out whole frames or recording days, (ii) quantifies how much the random split leaks, (iii) compares three classifiers on identical splits, (iv) reports performance per weather condition with uncertainty estimates, and (v) *measures* inference latency instead of asserting it.

> **Note on earlier numbers.** An earlier version of this README reported 93.25% accuracy from a random crop-level split. That number was not produced by the current pipeline and is likely optimistic for the reason above. It is intentionally not repeated here. All results in this repository are generated by the scripts below into `results/`.

## 1. Pipeline

```
COCO annotations ──► preprocess.py ──► crops (64×128 gray PNG) + metadata.csv
                                              │
                    ┌─────────────────────────┴───────────────┐
                    ▼                                         ▼
              evaluate.py                              train_svm.py
   (grouped CV, 3 models, weather subsets)      (deployed model + model_card.json)
                    │                                         │
                    ▼                                         ▼
     results/*.csv, *.md, *.png          hog_svm_parking.pkl ──► app.py (Streamlit)
                    ▲
           benchmark_latency.py  (results/latency.*)
```

`common.py` holds the preprocessing, HOG parameters and grouping logic so that training, evaluation, benchmarking and the app all use *exactly* the same code path.

### Preprocessing (`preprocess.py`)
1. Parse `_annotations.coco.json`; each annotation gives a bounding box `[x, y, w, h]` and a category.
2. Map categories to labels explicitly (`empty` → 0, `occupied` → 1). Unmapped categories are skipped and reported, never silently assigned to a class.
3. Crop the box (clipped to the frame), convert to grayscale, resize to 64×128 (`INTER_AREA`), save as lossless PNG.
4. Write `metadata.csv` with, for every crop: source image, `frame_id` (the original frame, with Roboflow augmentation hashes stripped), and `date` / `lot` / `weather` **when they can be recovered** (otherwise `unknown`; values are never guessed).

## 2. Methodology and Mathematics

### 2.1 HOG features
For a grayscale image *I*, gradients are computed with centered differences:

`Gx = I(x+1, y) − I(x−1, y)`,  `Gy = I(x, y+1) − I(x, y−1)`

giving magnitude `‖G‖ = √(Gx² + Gy²)` and unsigned orientation `θ = atan2(Gy, Gx) mod 180°`.

The 64×128 image is divided into 8×8-pixel cells (8×16 cells). Each cell accumulates a 9-bin histogram of θ, weighted by magnitude. Cells are grouped into overlapping 2×2 blocks (stride 1 cell → 7×15 = 105 blocks); each block concatenates 4 histograms (36 values) and is normalized with **L2-Hys**: `v ← v / √(‖v‖² + ε²)`, clip entries at 0.2, renormalize. Final dimension:

`105 blocks × 36 = 3780` features per crop.

Block normalization makes the descriptor less sensitive to *global* illumination changes. It does **not** make it invariant to everything: shadows, rain and glare change local gradient structure, which is exactly what the weather analysis probes.

### 2.2 Classifiers
Let `x ∈ ℝ³⁷⁸⁰` be a HOG vector and `y ∈ {0, 1}`.

* **Linear SVM** minimizes `½‖w‖² + C Σᵢ max(0, 1 − yᵢ′(w·xᵢ + b))` with `yᵢ′ = 2yᵢ − 1`. The margin is `2/‖w‖`. In the dual form the solution is `w = Σᵢ αᵢ yᵢ′ xᵢ` over the support vectors, so for a *linear* kernel the decision function collapses to a single dot product `w·x + b`. `benchmark_latency.py` times this form separately and verifies it agrees with `SVC.predict`. The app uses `probability=True`, which fits **Platt scaling** `P(y=1|f) = 1 / (1 + exp(A·f + B))` on internal cross-validated decision values; these probabilities can occasionally disagree with the hard prediction and are only as good as the calibration set.
* **Logistic Regression** models `P(y=1|x) = σ(w·x + b)` and minimizes log-loss plus an L2 penalty `(1/2C)‖w‖²`. It is also a linear classifier but optimizes a different loss, so the comparison with the SVM isolates the effect of the loss function.
* **Random Forest** averages many decision trees trained on bootstrap samples with random feature subsets (`√d` features per split). It can model non-linear interactions between HOG cells but is slower at inference and gives no single weight vector.

All models use default-style hyper-parameters (`C = 1`, 200 trees). Tuning on the evaluation folds would itself leak information; proper tuning requires a *nested* cross-validation (listed under Limitations).

### 2.3 Why random crop-level splits leak
Standard cross-validation assumes samples are i.i.d. Here they are not: crops from one frame share lighting and camera pose, and a car parked for hours appears in many consecutive frames. If such near-duplicates fall on both sides of the split, the test score measures partly *memorization* rather than generalization to new scenes.

`evaluate.py` evaluates two protocols on identical samples and models:

| Protocol | Splitter | What is held out |
|---|---|---|
| `random` (baseline) | `StratifiedKFold` | individual crops (leaky) |
| `grouped` | `StratifiedGroupKFold` (or `LeaveOneGroupOut` for lots) | whole groups: recording **days** if dates can be parsed, otherwise whole **frames** |

Grouping strength, strongest first: lot > date > frame. Frame grouping removes same-frame leakage but **not** leakage across consecutive frames of the same scene; date grouping reduces that substantially. The script prints which grouping was used and asserts that no group appears in both train and test. It also reports a **leakage audit**: the fraction of test crops whose source frame also appears in training.

### 2.4 Metrics
"Occupied" is treated as the positive class. We report accuracy, per-class precision/recall/F1 (`F1 = 2TP / (2TP + FP + FN)`), macro-F1, and pooled confusion matrices. Fold-level mean ± std is reported for each protocol.

### 2.5 Weather subsets and uncertainty
A single model is trained per fold; its **out-of-fold** predictions (each crop is predicted by a model that never saw its group) are then split by weather and scored per subset. Confidence intervals use a **cluster bootstrap**: whole groups are resampled with replacement (1000 resamples, percentile 95% CI), because crops within a group are correlated and resampling crops individually would give intervals that are too narrow. Subsets with fewer than 5 groups are flagged as unreliable.

Weather labels are *not* part of the Roboflow COCO export by default. See [Weather labels](#weather-labels) for how to supply them. If they are unavailable, the weather analysis is skipped rather than approximated.

### 2.6 Latency measurement
`benchmark_latency.py`: batch size 1, single thread (BLAS/OpenMP forced to 1 thread, Random Forest `n_jobs=1`), images pre-loaded (no disk I/O), warm-up calls discarded, every call timed with `time.perf_counter_ns()` over repeated passes, reported as median / mean / std / p95 / p99 for each stage (preprocess, HOG, predict) and end-to-end. Hardware and library versions are saved with the results. Latency depends heavily on the number of support vectors, which depends on the data, so numbers must come from running on **your** trained models and machine.

## 4. Reproducibility

```bash
# 0. Environment (Python 3.12 recommended)
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-experiments.txt

# 1. Data: download PKLot in COCO format into raw_dataset/train/
#    (needs _annotations.coco.json plus the images)

# 2. Crops + metadata (optionally add --meta-csv, see "Weather labels")
python preprocess.py --train-folder raw_dataset/train --output-dir processed_data

# 3. Experiments (seeded; identical samples/splits for every model)
python evaluate.py --data-dir processed_data --max-per-class 2000 --n-splits 5 --seed 42

# 4. Latency (run on the machine you want to report)
python benchmark_latency.py --data-dir processed_data

# 5. Model used by the Streamlit app
python train_svm.py --data-dir processed_data --max-per-class 2000
streamlit run app.py
```

Seeds, grouping strategy, class counts, library versions and the leakage audit are written to `results/run_info.json`. After a successful run, record your exact versions with `pip freeze > requirements-lock.txt` and consider pinning scikit-learn: a pickled model is only guaranteed to load with the version that created it.

### Weather labels
Weather is not in the COCO annotations. If your image filenames contain a recording date (e.g. `2012-09-11_15_57_38…`), you can supply a small CSV mapping date → weather (and optionally lot):

```csv
date,weather,lot
2012-09-11,sunny,PUCPR
2012-09-12,rainy,PUCPR
```

and run `python preprocess.py --meta-csv date_meta.csv`. In the original PKLot release the images are organized by lot / weather / date, so this table can be derived from the folder names; verify this against your copy before relying on it. The mapping is by date only, so use it only if the same date does not occur with different weather in different lots.

## 6. Limitations
* **Leakage is reduced, not eliminated.** Grouping by frame does not separate consecutive frames of the same scene; date grouping helps but days from one camera still share scene layout. Leave-one-lot-out is the strongest test of cross-site generalization and requires lot labels.
* **Subsampling.** Experiments use a class-balanced random subset (default 2000 per class) to keep feature extraction and SVM training fast; results on the full dataset may differ.
* **No hyper-parameter tuning.** Defaults are used on purpose. Nested CV would be needed for tuned comparisons.
* **Weather subsets can be small**, especially rainy; check `n_crops`, `n_groups` and the CIs in `weather_table.md`. Subset scores come from a model trained on all weather types, not from per-weather training or cross-weather transfer.
* **Single-crop classification with known slot positions.** The system classifies pre-cropped spaces; it does not detect or localize spaces, and the app processes one uploaded crop at a time.
* **Latency scope.** Benchmarks use pre-cropped 64×128 grayscale inputs on one CPU thread, so the preprocessing stage is a lower bound, and results do not transfer to other hardware (e.g. Raspberry Pi). No edge-device testing has been done.
* **Probability calibration** (Platt scaling) has not been evaluated under distribution shift. Note that scikit-learn ≥ 1.9 deprecates `SVC(probability=True)` in favour of `CalibratedClassifierCV`.
* **No comparison with deep learning** (e.g. a small CNN such as mAlexNet) has been run; claims about classical vs. deep methods should not be made from this repository alone.

## 7. Possible extensions
Leave-one-lot-out evaluation with lot labels; nested CV for tuning; adding a small CNN baseline on the same grouped splits; calibration analysis (reliability diagrams); threshold selection that trades off false "available" against false "occupied"; evaluating on a different dataset (e.g. CNRPark+EXT) to test cross-dataset transfer.
